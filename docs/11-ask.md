# 11. 물어보기 (T-Q)

가족 누구나 앱에서 아이 행동을 질문하면, 집 PC 에 상주하는 워커가 10초 안에 질문을 집어 Claude Code(Opus, 기존 구독)로
**DB 근거 기반 답변**(10단계 안내 포함)을 만들고, 자체 품질 검사(≥ 9.5)를 거쳐 앱에 올린다. 비용 0(무료 Cloudflare + 기존 구독).
이 저장소는 공개이므로 실제 자료·이름·날짜를 넣지 않는다(합성 픽스처 테스트아이/2020 만).

- 이 문서는 **앱·서버 쪽(T-Q1)** 과 **공용 정의(10단계·답변 스키마·금지어)** 의 정본이다. 워커(`tools/ask-worker`, T-Q2)는 이 정의를 그대로 쓴다.
- 구현 위치: 서버 `server/routes/ask.ts`(세션 API)·`server/routes/worker.ts`(워커 API)·`server/auth/worker.ts`(Bearer 인증)·`server/ask/*`,
  공용 `shared/ask-schema.ts`(zod)·`shared/ask-levels.ts`(10단계)·`shared/ask-forbidden.ts`(금지어), 화면 `src/pages/Ask*Page.tsx`·`src/components/ask/`.
- API 는 `05` 「물어보기」, 표는 `03` §2-ask, 보안(워커 토큰 위협 모델)은 `04` §3-2, 화면은 `06` S50·S51·S91.

## 1. 흐름

```
앱(가족)                     Cloudflare(D1)                    집 PC 워커
 질문 보내기 ──POST /api/ask──▶ ask_question(pending)
   ◀── 접수 + 즉시 결과(비슷한 알림장·자료, AI 없음) + 위급 신호 여부
                                      ◀── 10초마다 POST /api/worker/ask/claim ─── (원자적으로 집음, 리스 5분)
                                      ◀── progress answering → 근거 묶음 → claude(Opus) 답 작성
                                      ◀── progress reviewing → 독립 검토(지적 목록 → 코드가 점수 계산) → <9.5 면 지적만 고치는 재작성 1회
                                      ◀── POST /answer (스키마 검증 422)  → ask_answer, status=done
 5초마다 조회 ◀─ 접수 → 작성 중 → 검토 중 → 완료(답변 카드)
```

- 위급 신호(red flag)는 **서버가 결정적으로**(키워드, AI 없음) 판정하고, 앱도 같은 모듈(`server/ask/redflags.ts`)로 **쓰는 즉시** 경고한다.
  red flag 질문은 워커가 먼저 집고(`red_flag DESC`), 답은 **10단계 고정**(서버가 다른 단계를 422 로 거절).
- 워커 생존 표시: 워커 호출마다 `app_setting.ask_worker_seen_at` 갱신(D1 쓰기 절약을 위해 최대 60초에 한 번). 2분 안이면 「온라인」.
  오프라인이면 앱이 「집 PC가 켜지면 답변해요」 를 보여 준다.
- 실패: 시도 3번(리스 5분 만료 또는 워커 `fail`) 안에 못 끝내면 `failed`(`too_many_attempts` 등). 앱은 「답을 만들지 못했어요. 다시 질문해 주세요.」.

## 2. 10단계

모든 문서·프롬프트·화면 공용 정의(`shared/ask-levels.ts`). 단계 배지는 **숫자 + 제목 + 아이콘** 으로 보이고 색은 보조일 뿐이다
(1~3 안정 · 4~6 안내 · 7~9 주의 · 10 경고: 새 색 없이 기존 상태색 토큰 재사용).

| 단계 | 의미 |
|---|---|
| 1 | 아주 흔한 발달 과정 |
| 2 | 흔하고 며칠이면 지남 |
| 3 | 흔함, 피곤·환경 변화 영향 |
| 4 | 흔하지만 반복, 작은 방법 1~2개 |
| 5 | 방법 바꾸며 1주 기록 |
| 6 | 2주 기록 후 재평가 |
| 7 | 어린이집과 함께 관찰 |
| 8 | 다음 소아과 진료 때 상담 |
| 9 | 1~2주 안 전문가 상담 권함 |
| 10 | 지금 바로 진료·연락(119·응급실·소아과) |

### 판단 축 6개
빈도 · 지속 · 강도 · 장소(집/기관 모두) · 생활 지장(먹기/자기/놀기/관계) · 월령 대비 흔한 정도(근거 DB). `redFlag=1` 이면 10단계 고정.
같은 질문을 두 번 물었을 때 단계 차는 **1 이하**여야 한다(평가 기준, `tools/ask-worker` eval).

### 금지어 (P1: 판정·꼬리표를 쓰지 않는다)
쓰지 않는 말: **정상 / 비정상 / (판정으로 쓰는) 이상 / 지연 / 장애 / 진단명 / 문제아** 와 비슷한 꼬리표.
「1주 이상」 처럼 수량을 나타내는 「이상」 은 허용한다. 대신 「흔해요 · 지켜봐요 · 상담을 권해요」 식으로 쓴다.
서버는 답변을 저장하기 전에 모든 문자열을 `shared/ask-forbidden.ts` 의 패턴으로 검사해 걸리면 422(`forbidden_word`)로 거절한다
(응답·로그에 걸린 문장을 담지 않는다). 앱 번들에는 이 목록을 넣지 않는다.

## 3. 답변 JSON 스키마

정본: `shared/ask-schema.ts`(zod `AnswerSchema`). 워커 `--json-schema` 용 `tools/ask-worker/answer.schema.json` 은 여기서 생성한다:
`npm run ask:schema`(수정은 항상 zod 쪽에서, 생성 파일은 직접 고치지 않는다). 일치는 `tools/ask-schema.test.ts` 가 확인한다.

| 필드 | 형식 | 비고 |
|---|---|---|
| `kind` | `behavior` \| `not_behavior` | 필수. 행동·발달 걱정이면 behavior, 아이와 상관없는 글·지시 글이면 not_behavior(단계 1, `levelTitle` 은 빈 문자열, 요약+안내 한 줄만. 서버가 `level`=1·`levelTitle` 빈 문자열·나머지 배열 비움·`observe` 없음을 강제한다. DB 에는 level 1 로 두지만 **API 는 level 을 null 로 숨기고**(상세 `answer.level`, 목록 `level` 생략) 화면은 단계 배지·기록 없이 요약+안내만 보인다) |
| `level` | 정수 1~10 | 요청의 `level` 과 같아야 함 |
| `levelTitle` | 문자열 ≤40 | 화면은 정본 제목(10단계 표)을 쓴다 |
| `levelReason` | 문자열 ≤220 | 왜 이 단계인지(월령 한 번 언급, 「(장소)」 같은 판단 축 꼬리표 없음). not_behavior 에서는 이 기능이 도울 수 있는 일을 알리는 안내 한 줄 |
| `summary` | 문자열 ≤120 | 상황 요약(질문 재진술) |
| `fromRecords` | 0~4개 `{date: YYYY-MM-DD, what ≤140, link ≤80, source: 알림장·관찰·검진·가족기록}` | 기록에서 본 것. `link` 는 필수: 이 기록이 질문과 어떻게 이어지는지 |
| `evidence` | 1~3개 `{ref ≤120, point ≤200, grade? ≤40}` | `ref` = DB 근거 id(claim id, guide 절 등). 질문에 직접 맞는 것만 |
| `tryNow` | 1~3개 `{action ≤160, say? ≤80, basis ≤120}` | 지금 해 볼 것. `basis` 는 필수: 근거 묶음의 `ref`, 또는 정확히 `일반 권고`(묶음에 없는 일반 조언 — 화면에 작은 「일반 권고」 표시). 실제 개수는 아래 단계별 틀 |
| `avoid` | 1~3개 문자열 ≤100 | 피할 것 |
| `observe` | `{what ≤100, howLong ≤40, how ≤200}` | 관찰 방법(behavior 필수, not_behavior 는 없음) |
| `upIf` / `downIf` | 각 1~3개 문자열 ≤120 | 단계가 올라가는/내려가는 신호 |
| `forAsker` | **필수** ≤160 | 질문자 맞춤 한 줄. 가족 역할은 적힌 그대로(엄마·아빠·할머니·할아버지), 아버님·어머님 등 높임 호칭 금지 |
| `limits` | 선택 ≤160 | 근거 부족·알림장 한계 |

추가 키 금지(`additionalProperties: false`), 문자열은 1자 이상, 직렬화 JSON ≤ 60 KB(스키마 최대로 채워도 한도 안).

### 3-1. 단계별 답변 틀

`shared/ask-levels.ts` 의 `LEVEL_TEMPLATES` 가 정본이다. 워커 프롬프트(「단계별 답변 틀」)와 결정적 검사가 같은 정의를 쓴다. 틀을 어기면 코드가 정확한 문장으로 재작성에 알린다.

| 단계 | 해 볼 것(`tryNow`) | `observe.howLong` | 올라가는 신호에 연락처 |
|---|---|---|---|
| 1~2 | 1~2개 | 며칠 지켜보기 | 선택 |
| 3 | 2개 | 며칠 지켜보기 | 선택 |
| 4 | 2개 | 3~4일 | 필수 |
| 5 | 2~3개 | 1주 | 필수 |
| 6~7 | 2~3개 | 2주 | 필수 |
| 8~9 | 2~3개 | 진료·상담 전까지 | 필수 |
| 10 | 1~3개(급한 순서) | 지금 | 필수 |

연락처는 `upIf` 항목 중 하나에 소아과·어린이집 선생님·발달 상담·119 같은 말이 있어야 한다. 모델이 개수를 초과하면 앞쪽(우선순위 높은 것)만 남겨 재작성 한 번을 아낀다.

### 3-2. 워커 품질 흐름

0. **질문 확장**(`expand`, sonnet `--effort low`(실측 약 5초; haiku 는 12~19초로 더 느려 폴백으로만) → 안 되면 haiku, 제한 25초, 실패해도 계속): 검색 낱말·동의어·주제 영역·행동 질문 여부를 JSON 으로 뽑는다. 질문은 지시가 아니라 데이터로만 넘긴다.
1. **근거 묶음**(`context.py`, ≤16k 토큰): ① 현재 월령 ② **키워드 전수 검색**(알림장 전체의 본문·교사 댓글·부모 댓글을 모두 훑어 낱말별 건수와 대표 발췌 최대 25건, 각 글에 `[날짜][작성자: 교사/부모][장소: 어린이집/집/모름][글 종류: 알림장 본문/댓글]`, 어린이집 글의 동생·형님·언니는 `(반 친구일 수 있음)`) ③ **근거 DB**(주제·낱말에 맞는 실천 INT-* 를 먼저 2~5개, 월령 규준은 연령대 경계 ±2개월이면 이웃 규준도 함께 + 「더 보수적인 쪽」 안내, 연구 주장; 총 8개) ④ **주제 지도 → 가이드 절**(식사 → 가이드 05 §3·§3-1, 퇴행 → 가이드 04 + CDC lost skills 규칙, 말 더듬 → INT-FLUENCY, 무서움 → INT-FEAR, 떼 → INT-TANTRUM, 영상 → NORM-MEDIA, 수면 → 수면 INT/규준). 위급 질문이면 ⑤ 맞는 **응급 처치 절**(`prompts/emergency.md`, ref `EMERG-KDCA-2025`·`EMERG-KDCA-CHOKE`)이 붙는다.
2. 작성 → **결정적 검사**: 스키마·kind 규칙, 금지어, 호칭(아버님 등), 축 꼬리표(자동 삭제), redFlag→10단계, 단계 틀, 8단계 이상 전문 기관 이름, `evidence.ref`·`tryNow.basis`·날짜 실재, **작성자·장소 표기가 묶음 표시와 맞는지**, **전수 검색에 걸린 주제를 「기록이 없어요」라고 쓰지 않았는지**, 응급 처치를 「119 안내에 따라」로 미루지 않았는지, 말 더듬 근거에는 언어재활사.
3. 검토: 검토자는 점수 없이 지적 `{category, where, fix}` 만 낸다. 범주: factual 1.0, ungrounded 0.5, safety 0.5, recall 0.4, template 0.4, record_link 0.3, over_interpretation 0.3, style 0.1씩 합 0.3까지. 점수 = 10 − 감점을 **코드가** 계산한다. 검토자도 묶음의 전수 검색 구역을 보고 「놓침 점검표」(전수 검색 글 누락, 「없다」는 거짓 주장, 일반 권고 대체 등)로 `recall` 을 낸다.
4. 점수가 9.5 미만이면 **지적만 고치는 재작성 1회**("이것만 고치고 나머지는 그대로") → 재검토. 재검토는 이전 지적이 고쳐졌는지 확인하고, 새 지적은 factual·ungrounded·safety·recall 만 받는다.
5. 더 높은 점수를 게시한다. 9.5 미만이면 앱이 「품질 검사 기준보다 낮아 참고용이에요」를 보인다. 하한(기본 8.5) 미만이면 `low_score` 로 실패(나중에 다시 시도).

> 자체 검토는 근거 묶음만 보므로 묶음에 없는 놓친 기록은 못 잡는다. 그래서 묶음 단계에서 전수 검색으로 놓침을 줄이고, 독립 검토(사람 또는 골든 세트 평가)로 재현율을 따로 확인한다.

### 3-3. 다듬기 규칙 (워커 프롬프트 + 결정적 검사)

- **내부 규칙은 가족 글에 쓰지 않는다**: 근거 묶음의 `[내부 규칙 …]`(연령대 경계의 「더 보수적인 규준」 규칙)은 두 규준이 **실제로** 함께 들어갔을 때만 붙고, 검색 건수(「484건」)와 함께 내부 판단용이다. 「보수적인 쪽」「월령 규준 경계」「N건」이 답에 있으면 지적한다.
- **월령 규준**: 현재 월령이 규준 범위 안일 때만 쓴다(상한 이후에는 다음 연령대만: 36개월 이상이면 36~60 만, 12~35 규준 제외). 다음 연령대 시작 2개월 전(34~35개월)에만 이웃 규준이 함께 들어간다.
- **단계 보정**: 질문에서 뽑은 빈도·지속·영향·공격성(질문 확장의 `frequency`·`duration`·`impact`·`aggression`, 없으면 null)이 모두 null 이면 단계는 3 이하. 기록이 반복을 보일 때만 4단계까지(levelReason 에 기록 반복을 적는다). 위급은 제외.
- **근거는 직접 뒷받침하는 행동에만**: `tryNow.basis` ref 의 주제(`topics.json` 의 INT·NORM 접두어, 주제 가이드 파일)가 질문 주제나 행동 글과 맞지 않으면 `over_interpretation`. 아니면 「일반 권고」.
- **관련 없는 기록은 `fromRecords` 에서 뺀다**(`link` 에 「관련 없다」 금지).
- **말씨**: `summary` 는 질문자께 2인칭(「엄마가/는」 3인칭 금지), 위급이 아니면 summary·levelReason 에 「질환」「병」 금지. 식사 질문에 가이드 05 §3-1 이 있으면 기존 2주 저녁 기록(records/식사기록)을 이어 쓰도록 안내한다.
- **위급 처치 틀**: `emergency.md` 각 절 제목의 ref(A: EMERG-KDCA-CHOKE·EMERG-KDCA-2025, B: EMERG-FEVER-DROWSY, C: EMERG-SEIZURE(경련 중 가슴압박 금지), D: EMERG-POISON, E: EMERG-INJURY, F: EMERG-SAFETY, G: EMERG-SUDDEN-LOSS)를 읽어, 위급 규칙에 맞는 절들(여러 개 가능)과 그 ref 만 묶음에 붙이고 `basis` 로 허용한다. 규칙 → 절: 숨·호흡·막힘·파래짐 A, 의식·깨워도·반응·고열·탈수 B, 경련 C, 약·독 D, 외상·출혈 E, 자해·학대 F, 갑자기 못 함 G(삼킴은 A+D).

### 3-4. 결정적 검사의 HARD / SOFT 정책과 권장 단계

- **HARD**(재작성이 필요, 검토로 넘기지 않음): 스키마 위반, redFlag→10단계·kind, 금지어(판정·꼬리표·진단명), 내부 규칙·검색 건수 노출, 행동 질문이 아닌데 behavior(주입) / not_behavior 에서 기록 노출, 응급 처치를 「119 안내에 따라」로 미룸. **재작성에도 HARD 가 남고 첫 초안도 HARD 였을 때만 `checks_failed`**. 첫 초안이 HARD 없이 깨끗했으면 그 초안(더 나은 쪽)을 게시한다.
- **SOFT**(그 밖의 모든 지적: 단계 틀, 근거·날짜·작성자 표기, 호칭·말씨, 관련 없는 기록, 기록이 없다는 주장, 주제 대조 등): **절대 막지 않는다.** 재작성 때 지시문에 들어가고, 재작성 뒤에도 남으면 검토자 지적과 같은 감점표(범주별 고정 감점)로 **코드가 점수에서 뺀다**(`where` 는 「코드 검사」). 점수가 9.5 미만일 때만 재작성이 일어난다.
- **위급 질문**은 스키마·안전·응급 규칙만 적용한다(식사기록·주제·말씨·단계 보정·권장 단계 규칙은 적용하지 않는다). 예: 사탕에 걸려 숨 못 쉬는 질문이 「먹다가」 때문에 식사 주제로 읽혀도 식사 규칙이 걸리지 않는다.
- **「기록이 없어요」 주장 대조**: 흔한 낱말의 건수는 세지 않는다. 날짜 빈도 5% 미만인 낱말이 주장 대상(「기록이/근거가」 앞 1~3 낱말)과 겹치거나, 서로 다른 낱말 2개 이상이 한 글에 함께 걸리고 둘 다 겹칠 때만 알린다. 지적에는 낱말과 날짜 최대 4개만 싣고 건수는 싣지 않는다.
- **권장 단계(낮은 단계 안정화)**: 질문 글에서 규칙으로 계산한다 — 빈도·지속(늘·항상·자꾸·계속·매일·맨날·가만히 못·하루에 N번)이 있고 영향이 없으면 3, 빈도와 영향·지속이 함께 있으면 4, 한 번의 흔한 감정 표현이거나 신호가 없으면 2(위급은 없음). 프롬프트에 권장 단계와 이유를 보이고, 모델 단계가 ±1 밖이면 `levelReason` 에 기록·근거를 대야 한다(아니면 SOFT template). 4단계 이상 규칙은 그대로다.
- **진단 로그**: `onCheckIssues(stage, issues)` 훅으로 단계별 지적을 받고, 워커 로그(`check_issues`)에는 **범주 이름만**(예: `s:template,h:forbidden`) 남긴다. 지적 문장·질문·답은 남기지 않는다.

### 3-5. 교정 라운드(독립 검토 r5 대응)

- **권장 단계가 기본값**: 모델 단계는 권장과 같아야 한다. ±1 은 `levelReason` 이 특정 기록(날짜·알림장)이나 근거를 댈 때만(아니면 SOFT template). 보정은 위로만: (a) 남을 때리거나 무는 등 공격 행동 → 최소 4, (b) 4주 이상(한 달·몇 주째·N주째 N≥4·몇 달) → 5(생활 영향이 적혔으면 6), (c) 하던 것을 못 함·퇴행 → 최소 9(8 아님), (d) 말 더듬이 4주 이상 → 5~6 이고 「며칠 지켜보기」 금지. **(a)·(c)의 최소 단계 미만은 HARD(`level`)**, 나머지는 SOFT.
- **내부 표지 누수는 HARD `leak`**: 가족 글 칸(summary·levelReason·fromRecords.what/link·tryNow.action/say·avoid·observe·upIf·downIf·forAsker·limits)에 「권장 단계/보다」「(장소 모름)」「(반 친구일 수 있음)」「records/」「가이드 §」「guide:」「묶음」「전수」「INT-」「NORM-」 금지. ref 는 `evidence.ref`·`tryNow.basis` 에만.
- **저녁 식사 기록표**: 가이드 05 §3-1 이 묶음에 있으면 `context.py` 가 「가족이 <시작일>부터 2주 저녁 식사 기록표를 쓰고 있어요」를 사실로 싣는다(시작일은 가이드 글에서 읽는다). 「있다면·쓰고 계시면」「식사 기록은 없어요」는 SOFT ungrounded.
- **오래된·무관한 기록**: 12개월보다 오래된 `fromRecords` 는 link 에 변화 설명이 없으면 SOFT record_link(`today` 훅이 있을 때). 「지금과는 달라요」「관련 없어요」는 빼라고 한다.
- **규준 지어내기 금지**(프롬프트·검토 점검표), **단계 문구 모순**(「다음 진료 때」+「기다리지 말고」)은 SOFT template.
- `eval --save-answers` 는 not_behavior 의 level 을 null 로 저장한다.
## 4. 리드타임 목표

PC 가 켜져 있을 때 **p50 ≤ 3분, p90 ≤ 6분**(질문 → 답 게시). 단계별로 기록한다:
`wait_ms`(질문 → 워커가 집음, 목표 ≤ 10초) · `work_ms`(집음 → 답 업로드, 워커 보고) · `total_ms`(질문 → 게시, 서버 계산).
`/api/overview` 의 `ask.medianTotalMs7d`(최근 7일 중앙값)로 목표를 본다. 워커 오버헤드는 claude 호출당 약 5초(도구·MCP·설정 없는 플래그 조합 실측).

## 5. 개인 자료 취급

- 질문·답은 가족 자료(S1)다. D1 에만 있고 로그·오류 메시지·분석에 쓰지 않는다(로그는 경로·상태코드·시간만).
- 워커는 질문 본문을 로그에 남기지 않는다(id·시간·상태만). 설정·로그는 저장소·Drive 밖(`%USERPROFILE%\.yj-ask\`).
- 질문 삭제는 소프트 삭제(기록 삭제 정책과 같다: 가족 누구나).
- 즉시 결과(비슷한 알림장·자료)는 질문의 낱말로 `LIKE` 검색한다(AI 없음). 질문 글은 검색 외에 쓰지 않는다.
