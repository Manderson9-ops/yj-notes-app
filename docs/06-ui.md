### 2-1. 자료 탭 화면 (T-C2)

| 경로 | 화면 | 내용 |
|---|---|---|
| `/library` | S40 | 「건강 기록」 입구 카드 2장(검진 N건·성장 곡선) + 보고서/가이드/위키 묶음 카드(제목·설명 한 줄·검증 배지). 맨 위에 「자료를 마지막으로 갱신한 날」 한 줄. 검증 배지는 적재 때 원본 커밋이 기록됐고 **미통과일 때만** 「검증 미통과」(통과는 모든 문서가 같아 숨김) |
| `/library/doc/:slug` | S41 | 마크다운: 안전 렌더(원시 HTML·위험 링크는 글자 그대로, 링크 `rel=noopener`), 목차(제목 `#`/`##`) 접이식 + 점프, 본문 폭 38em·큰 글씨. HTML: `<iframe sandbox="allow-scripts">` 로 `/raw`(CSP `frame-src 'self'` 로 열림) |
| `/library/checkups` | S42 | `data-tone="serious"`. 검진 카드(회차·검진일·나이·종합 소견·참고 사항·발달 평가는 결과지 문구 그대로) + 계측 표(항목·값·결과지 백분위, 불확실 값이 있을 때만 판독 열) + 측정 조건 메모. `UNCERTAIN` 은 「판독 불확실」 배지 + 설명. 원본 사진 보기는 사진 지원 때(이번에는 없음) |
| `/library/growth` | S43 | 측정 종류 칩(키·몸무게·머리둘레·BMI), 직접 그린 SVG 차트(기준 3·50·97% 옅은 선, 아이 점 진하게, 판독 불확실은 빈 점), 점을 누르면(점이 하나면 바로) 값·날짜·측정 조건. 「판독」 행은 불확실할 때만(검진과 같은 규칙). 기준표 출처는 사람이 읽는 이름(코드 상수 `referenceName`, 모르는 id 는 원문), 「표로 보기」 대체(차트와 같은 정보 + 그 나이의 기준값). 차트 라이브러리 없음 |

- 화면 코드는 `src/features/library/`, 모두 `React.lazy` 로 분할(초기 번들 예산, Q-PERF). 표시 문구에 판정 어휘가 없는지는 e2e 가 검사한다.

## 3. 핵심 흐름

### 저녁 식사 기록 (목표 30초)
```
홈 [오늘 기록하기] → 종류 [🍚 저녁 식사] → 
 Q1 미리 알렸나 [O][X] → Q2 불렀을 때 [바로 옴][달래서 옴][안 옴] →
 Q3 떼쓴 시간 [0][5][10][15][20][25+][직접] → Q4 던지기·때리기 → Q5 먹은 양 →
 Q6 저녁 전 간식 → Q7 아팠나 → Q8 휴대폰 → (메모) → 기록자 [엄마…] → [저장]
```
- 질문은 한 화면에 하나씩, 고르면 자동으로 다음. 뒤로 가기로 수정.
- 저장 후 "이번 주 3번째 기록" 같은 사실만 보여 준다(칭찬·평가 문구 없음).
- 경고 조건 충족 시: "떼쓰기 25분 이상이 기록됐어요. 도움 받을 때 기준 보기 →" (가이드 링크).

#### S20 구현 메모 (`/logs/new`, `/logs/:id/edit`)
- 진입: 기록 탭의 「기록하기」 버튼(홈 「오늘 기록하기」는 홈 화면 작업에서 같은 주소로 잇는다).
- 순서: 종류 칩(아이콘+글자) → 질문(한 화면에 하나, 큰 칩, 고르면 자동 다음, 「이전」으로 되돌아가 수정) → 확인 화면.
- 확인 화면: 답 목록(누르면 그 질문으로 가서 고치고 바로 돌아옴) · 날짜(오늘/어제 칩 + 날짜 고르기) · 기록한 사람(엄마·아빠·할머니·할아버지·이모, 마지막으로 고른 사람을 이 기기에 기억) · 메모(선택) · 저장.
- 숫자 질문은 칩(정의의 `presets`) + 「직접」 입력(범위 검사). 선택 글 질문은 「건너뛰기」.
- 저장 후: "저장했어요" + "이번 주 N번째 기록"(수정이면 "이번 주 기록 N건") 같은 사실만. 경고 조건이면 "떼쓴 시간 25분 이상이 기록됐어요." + 「도움 받을 때 기준 보기」(`/library/<guide>`). 칭찬·평가 문구 없음.
- 끊긴 상태: "기기에 저장했어요 — 연결되면 자동으로 보내요". 상단 띠에 대기 건수. 연결되면 같은 id 로 보내 서버에는 한 건(멱등), 일시 오류는 2초부터 두 배씩(최대 60초) 다시 시도.
- 화면이 바뀔 때마다 새 제목으로 포커스가 옮겨 가 키보드·스크린리더 사용자가 처음에서 시작한다.

#### S21 구현 메모 (`/logs`)
- 위에서부터: 기록하기 버튼 · 못 보낸 기록 안내 · 종류 칩(전체/종류별) · 기간 칩(최근 2주/4주/전체) · 경고 목록(날짜·문구·가이드 링크) · 주차 비교 표 · 교차표 · 최근 기록(30건씩 「더 보기」).
- 주차 비교·교차표는 종류를 골랐을 때만(종류 없이는 안내 문구). 표는 좁은 화면에서 가로로 밀어 볼 수 있고 키보드로 초점이 간다.
- 기록 카드: 종류·날짜·기록자·핵심 답(정의의 `summary.highlight`)·메모, 「고치기」 「지우기」. 지우기는 **앱 안 확인 대화상자**(기본 포커스 「취소」, Esc 로 닫기). 브라우저 기본 `confirm` 은 쓰지 않는다.

### 알림장 찾기
검색어 입력(디바운스 300ms) → 결과 목록(날짜·첫 줄·일치 강조) → 상세 → 좌우 넘기기로 이전/다음 날.

## 5. 디자인 토큰 (`src/styles/tokens.css`)
- 색: `--c-bg`, `--c-fg`, `--c-accent`(파랑), `--c-warn`(주황), `--c-alert`(빨강), `--c-ok`(초록) — 라이트/다크 각각.
- 크기: `--fs-base: 17px`, `--fs-lg`, `--fs-xl`, `--tap: 48px`, `--radius: 12px`, `--space-1…6`.
- 아이콘: 이모지 대신 SVG 아이콘(일관 렌더링). 기록 종류는 아이콘 + 글자 함께.
- 테마: 기본·크레용·숲 3종(ADR-0007). 전체 토큰 계약·게이트는 `docs/design/theme-system.md`. 화면 코드는 토큰·공용 클래스만 쓰고 hex 를 직접 쓰지 않는다.
- S90 설정에 「화면 테마」(기본/크레용/숲)과 「더 보기 → 디자인 미리보기」(S91, 합성 자료로 전 컴포넌트·화면 시안; 모든 사용자에게 보임)를 둔다.

## 6. 홈·알림장 UX 결정 (T-C1)

답할 질문: 조부모가 480일치 알림장에서 원하는 날을 어떻게 찾는가. 아래는 구현에서 정한 것과 이유이다(바꾸면 이 절을 고친다).

| 결정 | 이유 |
|---|---|
| 목록은 「더 보기」 단추(한 번 30일, §7). 무한 스크롤 아님 | 화면이 갑자기 길어지지 않고, 끝까지 내려가도 하단 탭에 닿는다. 뒤로 가기 위치 복원도 단순 |
| 검색어·기간은 주소(`/notes?q=&p=`)에 둔다 | 상세에서 뒤로 오면 같은 목록이 돌아온다. 링크 공유·새로고침도 유지 |
| 기간 칩 기본값은 「전체」 | 낙말 검색이 기간에 가려 빈 결과가 되는 일을 막는다. 「최근 N달」 은 **가장 최근 알림장 날짜** 기준(`/overview` 의 `range.to`)이라 동기화가 늦어도 비지 않는다 |
| 일치가 있으면 발췌을 항상 보이고 첫 줄은 한 줄로 줄인다. 댓글 일치는 「댓글」 라벨 | 첫 줄이 길면 일치 부분이 잘려 안 보일 수 있다. 일치 강조는 색+굵기+밑줄(색 단독 금지) |
| 상세 이전/다음 날은 `replace` 로 이동, 위·아래 두 줄 배치, 스와이프는 만들지 않음 | 뒤로 가기 한 번이면 목록(위치 복원)으로. 긴 글에서도 단추가 손에 닿는다. 스와이프는 선택 사항이라 제외(가로 스크롤과 충돌 위험) |
| 목록에서 들어간 상세의 「알림장 목록」 단추는 history 로 돌아감(위치 복원), 홈 등 다른 곳에서 들어왔으면 `/notes` 로 이동 | 단추 이름이 거짓이 되지 않게 |
| 댓글은 「교사」·「보호자」 글자 라벨 + 왼쪽 선 색 + 바탕 면 | 색만으로 구분하지 않는다(색맹·흑백) |
| 홈 「마지막 동기화」 는 14일 초과 시 경고 상자(판정 문구 없이 경과 일수만) | docs/06 §4 |
| 홈·알림장은 `React.lazy` 묶음, `src/styles/notes.css` 는 그 묶음과 함께 내려받음 | 초기 번들 증가 최소화. `tools/size/check.ts` 는 이제 index.html 이 부르는 초기 파일만 기존 한도(+15 KB)로 재고, 지연 묶음은 별도 한도(60 KB, 제안값)로 잠 |
| 반(class) 필터 UI 는 만들지 않음(API 는 지원) | 반이 하나뿐인 자료로 보이고, 칩이 늘어 화면만 복잡해진다. 실제 자료에 반이 여러 개면 추가 |

홈(S10) 실제 구성(순서는 §7 로 바뀜): 최근 알림장 첫 카드 → 「오늘 기록하기」(→ `/logs/new`, 다른 카드가 만드는 화면) → 지난 알림장 2개 카드 → 자료 현황(마지막 동기화·알림장 일수·보고서·댓글·기간) → 최근 가족 기록(있을 때만). 숫자는 모두 `/overview` 값. 경고 배지는 아직 없다(경고 규칙 화면은 기록 카드 몫).

## 7. 실제 자료 점검 결과와 UX 결정 (T-E1)

답할 질문: 실제 자료(알림장 약 480일·문서 19개·검진 1건·가족 기록 0건)를 로컬에 넣고 조부모·부모 입장에서 써 보니 무엇이 불편했고 어떻게 고쳤는가. 자료 안의 문장은 적지 않고 **패턴**만 적는다(공개 저장소 규칙). 확인은 360×740 화면(기본·크레용·숲, 라이트·다크, 큰 글씨)을 직접 보고 했다. 바꾸면 이 절을 고친다.

### 7-1. 문제 → 조치 → 근거

### 7-3. 제한

- 위 확인은 한 명의 개발자가 데스크톱 Chromium 의 360×740 에뮬레이션으로 했다. 실제 조부모·실제 안드로이드 기기에서의 사용성 시험은 아니다.
- 안부 질문 건너뛰기는 글자 규칙(짧은 한 줄·물음표·「안녕하세요」)이라 규칙에 안 걸리는 인사는 첫 줄에 남는다.

### 7-5. 재평가 반영 (3차)

| 결정 | 이유 |
|---|---|
| 오프라인 전송 시험(흐름 3)은 「서버 행 2개, id 별 PUT 1~2번」 을 단언한다(「PUT 정확히 2번」 아님). mock 이 PUT 마다 `{id, at}` 을 남긴다 | 대기열은 **최소 한 번 전송**(at-least-once) 설계이고 같은 id 의 PUT 은 멱등이다. 연결 복구·화면 복귀·재시도 타이머가 겹치면 같은 기록이 한 번 더 갈 수 있고, 서버 행은 늘지 않는다. 지켜야 할 불변식은 「중복 행 0」 이지 「전송 1회」 가 아니다. 전체 실행 중 3번째 PUT 이 한 번 관찰됐고(원인 미확정) 단독 반복에서는 재현되지 않았다. 시험이 설계를 넘는 것(정확히 한 번)을 요구하지 않게 했다 |
| `QueueSyncGate`: 대기열 동기화 코드를 내려받다 실패하면 `online`·`visibilitychange` 때 새로 내려받아 다시 켠다 | 끊긴 채 앱을 열면 lazy 조각이 없어 동기화가 조용히 꺼진 채 남을 수 있다. 앱은 멈추지 않고(`QuietBoundary`), 연결이 돌아오면 스스로 켜진다. `React.lazy` 는 실패를 기억하므로 effect 로 직접 내려받는다 |
| 오류 본문 검사(`parseErrorBody`)는 모양이 어긋나면 그 항목만 버린다(`retryAfterSec` 음수·소수, `fields` 비문자열) | 서버 응답이 이상해도 오류 화면이 멈추지 않게. 단위 시험으로 고정 |
| 크레용 글꼴 부분 집합에서 숫자 0-9 를 뺐다(`size:check` 가 한도 여유 8 KiB 미만이면 경고) | 숫자는 본문 글꼴 + tabular-nums 규칙. 크레용 78,616 → 76,864 B. 자세한 내용은 `docs/design/theme-system.md` |
