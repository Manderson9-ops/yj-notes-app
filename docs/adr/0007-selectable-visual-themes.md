# ADR-0007: 고를 수 있는 화면 테마(기본·크레용·숲)

- 상태: 승인 (2026-10-02)
- 관련: docs/06-ui.md, docs/design/README.md, docs/design/theme-system.md

## 배경
관리자가 앱 디자인을 두 가지 그림체에서 따로 배워 각각 적용한 버전을 원했다.
1. 일본 애니메이션 「크레용 신짱」의 그림체
2. 미야자키 하야오(스튜디오 지브리) 작품의 그림체

선택지는 세 가지였다: 앱 안 테마 전환, 테마별 브랜치·배포 두 벌, 앱과 분리된 시안만.
관리자는 **앱 안 테마 전환**을 골랐다(2026-10-02). 저작권은 **그림체 특징만 배우고 캐릭터·로고·원화·대사는 쓰지 않는다**로 정했다.

## 결정
- 테마는 `<html data-theme="…">` 하나로 바꾼다. 값: `basic`(기본, 속성 없음과 같음), `crayon`, `forest`.
- 테마는 **CSS 토큰과 장식 SVG만** 바꾼다. 화면 구조·문구·접근성 트리·API 는 테마와 무관하다.
- 라이트/다크는 지금처럼 시스템 설정을 따르고, 테마마다 라이트/다크 토큰을 둔다(3 × 2 = 6 조합).
- 선택은 기기별 `localStorage`(`yj.theme`)에 둔다. 서버·D1 에 저장하지 않는다(가족 자료가 아님, 무료 한도 절약).
- 화면 이름은 상표를 피한다: 「기본」「크레용」「숲」. 영감 출처는 문서에만 적는다.
- 장식 폰트는 정적 UI 문구(앱 이름·제목·탭·버튼)에만 쓰고, 쓰는 글자만 남긴 부분 집합(subset) woff2 를 테마를 고를 때만 내려받는다. 본문·자료 글은 시스템 글꼴.

## 결과
- 이후 M2~M4 화면은 토큰·공용 클래스만 쓰면 세 테마가 자동 적용된다. 화면 코드에 테마 분기(`if theme`)를 두지 않는다.
- 6 조합 모두 대비 4.5:1(본문)·3:1(큰 글씨·UI 경계) 을 자동 테스트로 지킨다.
- 테마 CSS·SVG 는 번들에 항상 들어간다(작음). 폰트만 지연 로드.

## 검토한 대안
- 테마별 브랜치·배포 두 벌: 비교는 쉽지만 기능 개발 때마다 세 갈래를 맞춰야 해서 기각.
- 분리 시안만: 실제 앱에서 쓸 수 없어 기각(대신 앱 안 「디자인 미리보기」 화면을 둔다).
- 서버 저장(가족 공통 테마): 조부모·부모 취향이 다를 수 있고 D1 쓰기가 늘어 기각.
- 실제 캐릭터·장면 이미지 사용: 공개 저장소 저작권·상표 위험으로 기각.
