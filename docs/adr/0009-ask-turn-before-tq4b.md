# ADR-0009: 물어보기 대화(T-Q5)를 초안 먼저 보이기(T-Q4b)보다 먼저 만든다

- 상태: 승인 대기 (2026-11-19, T-Q5 PR 에서 함께 검토)
- 관련: docs/11-ask.md §3-8·§3-9, docs/12-ask-worker.md, docs/10-roadmap.md T-Q 표

## 배경
물어보기 개선은 원래 T-Q4a(워커 속도·실패 처리) → T-Q4b(초안 먼저 보이기·서버 냉각) → T-Q5(대화) 순서로 나뉘어 있었다.
T-Q5 는 T-Q4b 의 초안 단계·냉각을 재사용하도록 설계됐다. 그런데 지금 사용자가 바라는 것은 「질문 → 대답」으로 끝나지 않고
**「질문 → 대답 → 확인(재질문) → 대답」** 으로 이어지는 대화이고, 출시 순서는 정해진 바 없다. 지금 코드에는 `followup`·`ask_turn` 이 없다.

## 결정
T-Q4b 없이 T-Q5 를 먼저 만든다. T-Q4b 가 올 때 턴 경로에 이어 붙일 수 있도록 다음처럼 가른다.

- **만들지 않는 동작**(T-Q4b 소관): 턴 초안 게시(`/draft`)·「검토 중인 초안」 표시, 확정 교체 알림, 미검토 확정(`reviewScore: null`),
  서버 냉각(`retry_after`), `claude_auth` 되돌리기·`authRefunds`, ping 상태 `paused_auth`, 앱 2초 조회.
- **열은 미리 만든다**: `ask_turn` 의 `draft_json`·`draft_at`·`draft_ms`·`retry_after`·`auth_refunds` 는 만들어 두되 쓰지 않는다.
  T-Q4b 의 마이그레이션이 `ask_question` 에만 열을 더하므로, 지금 만들지 않으면 아무도 만들지 않게 된다.
- **마이그레이션 번호**: 대화 마이그레이션은 다음 빈 번호 `0011_ask_turn.sql` 이다(`ask_question` 의 `card_updates`·`red_lock`·`origin_question_id` 포함).
  T-Q4b 의 마이그레이션은 그 뒤 번호를 받는다.
- **짧은 답은 확정 흐름이다**: 작성(Opus) → 기계 검사 → 검토(`ASK_FOLLOWUP_REVIEW_MODEL`, 기본 sonnet) → 점수가 목표 미만이면 재작성 1회·재검토
  → 게시 하한(`ASK_MIN_PUBLISH_SCORE`) 이상이면 확정, 미만이면 `low_score` 로 실패. 카드 검토가 실패하면 시도 3회 뒤 `card_status='failed'`.
- **냉각 없음**: 턴 실패는 지금 질문 실패처럼 곧바로 다시 집힌다.
- **조회 간격**: `workerOnline`(seen 2분 이내 **또는** 리스가 살아 있는 작업)·`threadActive` 에 따라 5초·30초·60초.

## 결과
- 가족은 답 카드 아래에서 이어서 묻고 짧은 답을 받는다. 필요할 때만 카드가 새 버전으로 바뀐다.
- 턴의 짧은 답은 검토 전에 보이지 않는다(초안 없음). 체감은 첫 질문과 같은 수준이다.
- T-Q4b 를 넣을 때 턴 경로에도 초안 단계를 이어 붙이는 작업이 생긴다(위 「만들지 않는 동작」 목록이 그 작업 목록이다).
- 위급 턴은 미검토 카드 게시와 5초 냉각을 아직 갖지 않는다. 도구 쪽 실패가 이어지면 카드 3회를 짧은 시간에 다 쓰고
  `card_status='failed'` 가 될 수 있다(화면은 이전 카드 위에 위급 경고를 고정한다). 지금 위급 질문의 동작과 같은 수준이다.

## 검토한 대안
- T-Q4b 를 먼저 끝내고 T-Q5(기각: 사용자가 원하는 것은 대화이고, 초안 먼저 보이기는 속도 개선이라 대화를 막을 이유가 없다).
- 두 카드를 한 PR 로(기각: 카드 1장 = PR 1개, 품질 하락 원인을 카드 단위로 가르기 위해).

## 되돌리기
이 카드를 멈추고 T-Q4b 부터 한다. 서버만 되돌릴 때 워커를 먼저 되돌리면 안 된다 — Pages 환경변수 `ASK_TURN_CLAIM=0` 으로 먼저 턴 claim 을 끈다.
